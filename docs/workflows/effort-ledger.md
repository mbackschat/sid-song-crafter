# Record effort on the next musical case

Start this ledger in the owning study when the next real musical case is authorized. Record the entire route from source intake to accepted complete output, including setup, musical decisions, rejected trials, troubleshooting and retention. A technical onboarding example does not substitute for that case. [PLAN.md](../PLAN.md#workbench-value-and-usability-assessment) owns whether a case is active.

Copy this small record; use `not recorded` for unavailable observations. Link recipe receipts rather than transcribing their per-stage timings. Record a row at a meaningful checkpoint, not every tool call.

| Case field | Value |
| --- | --- |
| Source, scope, intended character and target hardware | Source/brief links |
| Operator and agent host/model/settings | Actual participants and configuration |
| Starting tools/repertoire; new setup needed | Existing versus case-specific preparation |
| Started; first playable; complete candidate; accepted complete output | ISO timestamps; leave pending milestones explicit |
| Acceptance and ending verdict | Human review links and exact scope |

| Checkpoint / activity | Human active minutes | Agent elapsed minutes | Tool receipt / execution time | Exposed cost and currency | Revision, failure or intervention | Result / evidence |
| --- | ---: | ---: | --- | --- | --- | --- |
| Source intake and setup | not recorded | not recorded | Receipt link | not recorded | Description or none | Source/reduction link |
| Arrangement and sound revisions | not recorded | not recorded | Receipt link | not recorded | Selected and rejected revisions | Comparison/verdict link |
| Complete export and ending | not recorded | not recorded | Receipt link | not recorded | Description or none | Full-delivery link |
| Troubleshooting and retention | not recorded | not recorded | Receipt link | not recorded | Description or none | Recovery/cleanup link |

Human active time excludes waiting; end-to-end elapsed time includes waiting and must be reported separately. Keep overlapping agent and tool intervals separate rather than adding them into a fictitious total. Identify reusable setup costs separately from work specific to this song. Subscription/API cost not exposed by the host is unknown, not zero.

At closure, identify which existing instruments, recipes, source knowledge and checks actually helped, what required new work, and the largest observed friction. Report measured cost and completion milestones. A single case has no counterfactual: comparative composition-effort savings remain unproven until comparable observations exist. Do not retrospectively estimate earlier human effort from Git timestamps or renderer timings, or open extra musical cases solely to fill this ledger.
