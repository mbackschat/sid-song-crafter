# Verification and listening evidence

Use separate evidence for musical fidelity, correct execution, and sound quality. Return to the [research index](../README.md).

- [Verification guide](verification.md): source checks, chip models, timing, emulation, and hardware evidence.
- [Full-song validation](../../fuer-elise-validation.md): exact CPU writes, sampled register states, audio health, and native VICE execution.
- [Headless audio](../../audio-workflow.md): renderer setup, PCM checks, recording, and known environment limitations.
- [Sound-design repertoire](../composition/sound-design-repertoire.md): listening comparisons and the criteria for promoting experiments into reusable instruments.

A passing CPU test does not prove good sound. A plausible WAV does not prove the intended driver timing. Record the source, chip model, player revision, measurement method, and listening status with each result.
